## 2. Storage and privacy rules

1. **Recordings do not belong in GitHub.** Screen and audio recordings, raw transcripts, and screenshots containing personal data stay in the access-controlled private folder agreed with the participant, reachable only by the research team. This includes issues, pull requests, and issue comments.
2. **This repository stores metadata only:** slot ID, evidence ID, task, artifact type, private storage reference, retention date, and verification initials. A private storage URL may be recorded here only if it is access-restricted and not indexed; otherwise record the folder name and file name instead of the URL.
3. **Retention:** delete all recordings 90 days after the final session ([`usability-test-protocol.md`](./usability-test-protocol.md) §5). Record the deletion date in §3.
4. **Pseudonyms only.** Rows use slot IDs (P1–P8). Names, emails, wallet addresses, and employer details never enter this file or any committed note.
5. **Consent before capture.** No row may be marked `held` unless the matching consent ID in §4 is complete and the verbal confirmation timestamp is recorded.

## 5. Withdrawal, deletion, and audit procedure

1. **Withdrawal:** on request, delete the recording and transcript, mark the consent row `withdrawn`, mark the evidence rows `excluded`, and remove the session from synthesis. Target: within 5 business days.
2. **Deletion:** at the retention date, delete media, record the deletion date and the person who deleted it in §3, and keep the register rows so the audit trail survives.
3. **Maintainer audit:** for any claim in a report, check that (a) an evidence ID exists in §3, (b) the matching consent ID in §4 is complete, (c) the quote is verbatim and pseudonymous, and (d) the report cites the evidence ID. Claims that fail (a) or (b) are removed from the report.
